# Project Governance

This document describes the governance model for this project.

## Core Team

The project is managed by a core team of maintainers. Core team members are responsible for:

- Reviewing and merging pull requests
- Managing project releases
- Defining project roadmap and direction
- Resolving technical disputes
- Maintaining community health

## Decision Making Process

Major decisions are made through consensus among core team members. The process is:

1. **Proposal**: Any core team member can propose a change via GitHub issue or pull request.
2. **Discussion**: Proposals are discussed openly for at least 72 hours.
3. **Consensus**: Core team members vote using +1 (approve), 0 (abstain), or -1 (veto).
4. **Resolution**: If consensus is reached (no vetoes), the proposal is accepted.

## Contribution Process

1. Fork the repository and create a feature branch.
2. Make your changes following the project's coding standards.
3. Write or update tests as needed.
4. Submit a pull request with a clear description of changes.
5. Ensure all CI checks pass.
6. Request review from at least one core team member.

## Code Review Guidelines

- All code changes must be reviewed by at least one core team member.
- Reviews should be constructive and respectful.
- Reviewers should focus on correctness, maintainability, and security.
- Changes requiring significant discussion should be flagged with the "needs discussion" label.

## Release Process

1. Core team agrees on release scope and timeline.
2. Release candidate is created and tested.
3. Final release is tagged and published.
4. Release notes are written summarizing changes.

## Community Roles

### Contributors
Anyone who submits a pull request, reports a bug, or participates in discussions.

### Committers
Contributors who have demonstrated sustained contribution quality and are granted write access to the repository.

### Maintainers
Core team members with full administrative access to the repository.

## Conflict Resolution

If consensus cannot be reached, the following escalation path applies:

1. Further discussion with additional context.
2. Mediation by a neutral third party.
3. Final decision by the project lead.

## Code of Conduct

All participants in this project are expected to follow the [Code of Conduct](CODE_OF_CONDUCT.md).

## Changes to Governance

Changes to this governance document require approval from at least 2/3 of core team members.
